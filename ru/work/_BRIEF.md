## Шаг 2. Переведи

Полный перевод авторского текста. Это НЕ пересказ, НЕ адаптация, НЕ выборка.
Каждое предложение оригинала должно найти соответствие в переводе.

### Структуру Markdown сохраняй ТОЧНО

* Те же уровни заголовков (`#`, `##`, `###`) и те же номера разделов:
  `## 4.3 Stack` → `## 4.3 Стек`. Номер не меняется, заголовок переводится.
* То же количество и та же последовательность абзацев, списков, таблиц,
  блоков кода и рисунков.
* Между блоками — ровно одна пустая строка, как в оригинале.

### Что переводить

| Элемент | Как |
|---|---|
| Заголовки | Переводить, номер сохранять |
| Абзацы | Переводить полностью |
| Списки (`- ...`) | Переводить, маркер `-` сохранять |
| `**Table N.N: ...**` | → `**Таблица N.N: ...**`; ячейки переводить, значения кода (`[]`, `true`, `O(n)`) — нет |
| `*Figure N.N: ...*` | → `*Рисунок N.N: ...*` |
| `![...](images/fig-N.N.png)` | alt-текст перевести, **путь файла не менять** |
| Ссылки `[1]`, URL, версии | Не менять |
| Названия книг/статей | Оставить как в оригинале |

### Что НЕ трогать

* **Блоки кода** — вообще. Fenced-блоки (```), язык после ```, содержимое строк
  остаются без изменений. Единственное исключение: английские комментарии
  `// ...` и `/* ... */` можно перевести на русский, если это не меняет смысл
  программы (например `// stack size` → `// размер стека`).
* **Идентификаторы Rust**: `Vec`, `push`, `pop`, `usize`, `Self`, `Cargo`,
  `rustc`, `rustup`, `HashMap`, имена функций/переменных/полей, ключевые
  слова — не переводить и не переименовывать.

### Стиль

* Нейтральный технический русский. Без разговорности, без пафоса, без
  домыслов и собственных пояснений.
* Не сокращать текст. Перевод примерно на 5–15 % длиннее оригинала.
* Кавычки — «ёлочки» `«…»`. Тире — `—` (длинное).
* Числа, обозначения сложности (`O(n)`, `O(n²)`), имена алгоритмов
  (Quick Sort → быстрая сортировка) — по глоссарию.
* Сохраняй авторскую последовательность объяснений.
