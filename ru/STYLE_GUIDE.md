# Руководство по переводу русского издания RustBook

Документ обязателен для всех переводчиков русского издания.

## 1. Задача

Переводится **полный авторский текст** книги QMHTMY/RustBook
(оригинальное английское издание, PDF `rust-book-en-us-shieber.pdf`).
Перевод должен быть полным, точным и стилистически цельным.

## 2. Что переводится, а что нет

| Элемент | Действие |
|---|---|
| Абзацы прозы | Переводить полностью |
| Заголовки разделов | Переводить, **сохраняя номер** (`## 4.3 Стек`) |
| Подписи к рисункам | Переводить (`Рисунок 4.1: Стек`) |
| Подписи к таблицам | Переводить (`Таблица 4.1: Операции со стеком`) |
| Содержимое таблиц | Переводить (кроме имён API и значений кода) |
| Списки | Переводить, сохраняя маркеры `-` |
| **Блоки кода** | **Не трогать** (кроме перевода комментариев, см. п. 4) |
| Идентификаторы Rust | Не переводить |
| Ссылки `[1]`, URL | Не переводить |
| Названия книг, статей | Оставить как в оригинале |

## 3. Структура Markdown — не изменять

Переводчик получает исходный Markdown-файл и возвращает Markdown-файл
**той же структуры**. Обязательно сохраняются:

* порядок и количество блоков;
* уровни заголовков `#`, `##`, `###` и их номера;
* порядок и содержимое блоков кода (``` fences и язык);
* изображения `![...](images/fig-N.N.png)` — **путь и имя файла не менять**,
  менять только текст внутри `![...]` (alt-текст);
* подписи `*Рисунок N.N: ...*` — менять только текст подписи;
* таблицы — та же структура Markdown-таблицы и то же число строк/столбцов;
* пустые строки между блоками (ровно одна).

## 4. Код

* Ключевые слова Rust, имена типов, функций, методов, полей и переменных
  **не переводятся** и **не переименовываются**.
* Комментарии на английском языке переводятся на русский — **только если
  это не меняет смысл программы** и не превращает комментарий в инструкцию
  по выполнению кода.
* Комментарии вида `// stack size` → `// размер стека`.
* Номера строк, если они присутствуют, сохраняются.
* Никогда не заменяйте реальный код псевдокодом и не сокращайте листинги.

## 5. Стиль перевода

* Тон: нейтральный технический, без разговорности и без пафоса.
* Сохраняйте авторскую манеру и последовательность изложения.
* Не добавляйте собственных пояснений, примеров и оценок.
* Не сокращайте текст: перевод должен быть примерно на 5–15 % длиннее
  оригинала из-за особенностей русского языка.
* Углублённые или родовые термины переводите по глоссарию
  (`ru/glossary.md`); приоритет глоссария выше любых других соображений.
* Сокращения вроде ADT, LIFO, BFS, DFS оставляйте как есть, при первом
  употреблении можно дать расшифровку: `абстрактный тип данных (ADT)`.
* Числа, версии (`1.58`), команды (`cargo build`) — без изменений.
* Кавычки: русские «ёлочки» `«…»`.
* Тире: `—` (длинное), без пробела перед ним.

## 6. Контроль качества (обязательно)

После перевода запускается автоматическая проверка
(`tools/check_translation.py`), которая проверяет:

1. совпадение количества и типов блоков с оригиналом;
2. побайтовое совпадение блоков кода;
3. наличие всех изображений и корректность путей;
4. совпадение числа строк и столбцов таблиц;
5. соответствие номеров заголовков;
6. отсутствие непереведённых английских абзацев (эвристика).

Если проверка сообщает об ошибке, их нужно исправить до сдачи главы.

## 7. Порядок работы

1. Прочитать `ru/glossary.md`.
2. Перевести файл целиком, не разбивая его на несвязные куски.
3. Запустить `tools/check_translation.py <файл>`.
4. Исправить найденные ошибки.
5. Сообщить о готовности и список найденных проблем в оригинале.
